# SDK Demos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port all 21 SDK demos of the RN boilerplate to working Android screens under a new "Device APIs" section, with one shared `PermissionGate`.

**Architecture:** One registry (`feature/example/sdk/SdkDemos.kt`) lists every demo (id, title, subtitle, screen); one route `SdkDemoRoute(id)` in the Home graph dispatches to it, so adding a demo is one registry entry. Each demo lives in `feature/example/sdk/<demo>/` as a stateless screen plus, where there is logic, a ViewModel or pure functions that are unit-tested; hardware calls stay in thin wrappers that are checked on the emulator and the physical device (spec §8). Permission flow lives once in `core/permission/`.

**Tech Stack:** Compose M3, Hilt, CameraX 1.6.2 + ML Kit barcode-scanning 17.3.0, biometric 1.1.0, WorkManager 2.12.0 + hilt-work 1.4.0, Media3 1.11.1, play-services-location 21.4.0, androidx.browser 1.10.0, Play review-ktx 2.0.2, ZXing core 3.5.4, exifinterface 1.4.2, Room (existing `ExampleDatabase`).

**Spec:** `docs/superpowers/specs/2026-10-30-kotlin-android-starter-design.md` (§6 demo table, §3, §8, §9.1). **Behavior reference** (labels, numbers, messages per demo): `docs/superpowers/plans/2026-10-31-05-sdk-demos-reference.md` — every task's copy and constants come from its section there; this plan does not repeat them.

## Global Constraints

- minSdk 24; "fitur yang butuh API lebih tinggi wajib punya fallback yang ditampilkan jelas di layar" — every API-gated path shows its fallback text from the reference on older devices.
- All dependencies through `gradle/libs.versions.toml`; latest stable versions (listed above).
- "Setiap demo yang butuh izin memakai satu komponen `PermissionGate` bersama."
- Anti-goal: "Demo yang 'ada halamannya' tapi tidak benar-benar berfungsi di device." No placeholder screens except live-photo, which the spec defines as an explanation page.
- `core/*` never imports `feature/*`; `feature/example` stays deletable (its manifest entries, providers and workers live with it or are removable in one place, documented in `docs/examples.md`).
- Strings in `values/` and `values-in/`; keys prefixed `sdk_<demo>_`; `TranslationCompletenessTest` stays green. Indonesian is authored (RN has none), casual-formal like the rest of `values-in`.
- Tests: hardware-backed demos test only their logic (ViewModel / pure functions) (spec §8); screens get a Robolectric test where they have logic-driven UI states.
- Proof command for every task: `./gradlew testDebugUnitTest ktlintCheck assembleDebug`.
- Every demo is opened once on the emulator (Pixel_9, API 36) before its task is committed; hardware demos (camera/QR, biometric, PiP, contacts, calendar) are listed for the user's physical-device pass (spec §6 Verifikasi).

## Review Focus

1. **Permission denied twice / "Don't ask again"** → the gate switches to "Open Settings" and returns to the content after the user grants it in Settings and comes back (re-checked on resume). Test in Task 1.
2. **Leaving a screen that changed window state** (payment-code brightness/keep-on/secure, status-bar icons, PiP) → the app's own state is restored exactly, including dark-theme icon colors. Tests in Tasks 3 (WindowTreatmentsTest) and 6 (PictureInPictureTest); status-bar restore is checked on the emulator in Task 1.
3. **Database upgrade from Plan 4** (Todos v1 → v2 with transactions) → existing todos survive. Test in Task 2.
4. **QR seen continuously by the camera** → exactly one result sheet until it is closed. Test in Task 5.
5. **Rotation / process death mid-demo** (typed PIN, selected options, pending notification count) → selections survive (`rememberSaveable` / `SavedStateHandle`); secrets (PIN text) are not saved to state. Test in Task 6 (PIN) and the per-screen tests.
