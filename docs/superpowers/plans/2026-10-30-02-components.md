# Compose Component Examples Implementation Plan (Plan 2 of 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show how to use Jetpack Compose / Material 3 components in this starter kit through four example pages and a validated form example, with every M3 color role mapped to the RN tokens so stock components look on-brand.

**Architecture:** No wrapper component library (user decision, spec §5.2). Pages live in `feature/example/components/` and use M3 components directly; patterns M3 lacks (avatar initials, skeleton, empty state, banner alert) are small `private`/`internal` composables inside the page that shows them. The form example follows the Screen/ViewModel split with pure, unit-tested validation.

**Tech Stack:** Compose BOM + Material 3 (already present), material-icons-core, Navigation Compose, Hilt, Robolectric + Compose UI test. No new libraries.

**Spec:** `docs/superpowers/specs/2026-10-30-kotlin-android-starter-design.md` (§5.2 component decision, §6 Komponen + Form)
**Reference source:** `D:\RN\rn-expo-boilerplate\src\app\(public)\example\components\*.tsx`, `src\app\(public)\example\form.tsx`

## Global Constraints

- Branch `feat/foundation` (user: stay on this branch). Toolchain from plan 1 unchanged (AGP 9.4.0, Kotlin 2.4.21, compile/target SDK 37, minSdk 24).
- No new dependencies. No wrapper components in `core/` (spec §5.2): pages call M3 composables directly.
- `core/*` must never import `feature/*`; everything in this plan except Task 1 lives under `feature/example/`.
- No hardcoded `Color` in pages; use `MaterialTheme.colorScheme` or `AppThemeTokens.colors`.
- Every user-visible string in `values/strings.xml` **and** `values-in/strings.xml` (TranslationCompletenessTest enforces parity). Demo-only sample data (e.g. "Ada Lovelace") may be code literals.
- Accessibility: icon-only controls have a `contentDescription`; clickable custom rows use `Role.Button`; touch targets ≥ 48dp (M3 defaults satisfy this).
- Tests: Robolectric `@RunWith(AndroidJUnit4::class)` + `@Config(sdk = [36])`; compose tests use `androidx.compose.ui.test.junit4.v2.*`; ViewModel tests never use a file-backed DataStore (Windows JVM rename bug) — use `testing/InMemoryPreferencesDataStore.kt` if needed.
- Proof command: `./gradlew testDebugUnitTest ktlintCheck assembleDebug`.

## Review Focus

1. **Long text in buttons, chips, list items and snackbars** → truncates with ellipsis or wraps, never pushes trailing content off screen (RN demo has a deliberately long ListItem title). Test in Task 4.
2. **Double-tap on a loading button** → action fires once; button disabled while loading. Test in Task 2 (and the form submit in Task 6).
3. **Form submit while invalid / editing after a failed submit** → errors show on submit, then update live as the user types (RN react-hook-form default: validate on submit, re-validate on change). Test in Task 6.
4. **Non-dismissable dialog** → back press and outside tap do not close it; only its button does. Test in Task 5.
5. **Dark mode** → stock M3 components (FAB, filled tonal button, chips, switch, snackbar) use mapped token colors, not M3 purple defaults. Test in Task 1.

**Interfaces:**
- Produces:
  - `enum class FormField { NAME, EMAIL, PHONE, PASSWORD, BIO }`; `data class FormValues(val name: String = "", val email: String = "", val phone: String = "", val password: String = "", val bio: String = "")`.
  - `fun validate(values: FormValues): Map<FormField, Int>` (value = `@StringRes` message). Rules from RN `form.tsx`: name required → `form_error_name_required` ("Name is required"); email required → `form_error_email_required` ("Email is required"), else must match `^[^\s@]+@[^\s@]+\.[^\s@]+$` → `form_error_email_invalid` ("Invalid email address"); phone required → `form_error_phone_required` ("Phone is required"), else length < 10 → `form_error_phone_min` ("Phone must be at least 10 digits"); password required → `form_error_password_required` ("Password is required"), else length < 8 → `form_error_password_min` ("Password must be at least 8 characters"); bio length > 200 → `form_error_bio_max` ("Bio too long"). "Required" means blank after trim.
  - `data class FormUiState(val values: FormValues = FormValues(), val errors: Map<FormField, Int> = emptyMap(), val submitAttempted: Boolean = false, val submitting: Boolean = false, val submitted: FormValues? = null)`.
  - `@HiltViewModel class FormExampleViewModel @Inject constructor() : ViewModel() { val state: StateFlow<FormUiState>; fun onChange(field: FormField, value: String); fun submit(); fun clear() }` — errors are hidden until the first `submit()`; after that every `onChange` re-validates; `submit()` with errors sets them and does nothing else; valid → `submitting = true`, `delay(1500)`, then `submitted = values`, `submitting = false`; `submit()` while `submitting` is ignored; `clear()` resets to `FormUiState()`.
  - `@Composable fun FormExampleScreen(state: FormUiState, onChange: (FormField, String) -> Unit, onSubmit: () -> Unit, onClear: () -> Unit, onBack: () -> Unit)` — `OutlinedTextField` per field (labels Full Name / Email / Phone / Password / Bio, placeholders from RN), error text as `supportingText` with `isError`, password field with visibility toggle, bio multi-line with counter "n/200"; buttons Submit (shows "Submitting…" + progress and disabled while submitting) and Clear (outlined); when `submitted != null`, an `OutlinedCard` with a success banner "Submitted" / "These are the values the form handed over." and each `field: value` in `bodySmall` monospace. Screen uses `imePadding()` so fields stay above the keyboard.
