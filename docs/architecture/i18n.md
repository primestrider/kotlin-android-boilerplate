# Internationalization

Supported languages: English (`en`, fallback) and Indonesian (`id`).

## Files

- `app/src/main/res/values/strings.xml` - English strings (default).
- `app/src/main/res/values-in/strings.xml` - Indonesian strings. Android uses the legacy `in` qualifier for Indonesian.
- `app/src/main/res/resources.properties` - `unqualifiedResLocale=en-US`, so `values/` is declared as English.
- `core/i18n/AppLanguage.kt` - `AppLanguage` enum and `resolveLanguage(appLocaleTag, deviceTag)`.
- `core/i18n/LanguageController.kt` - `current()` / `set(language)` over `AppCompatDelegate` application locales.

`androidResources { generateLocaleConfig = true }` generates `locales_config.xml` from the resource folders,
which enables the system per-app language picker (Android 13+). AppCompat's `AppLocalesMetadataHolderService`
with `autoStoreLocales=true` persists the choice and re-applies it on older versions, so no DataStore key is
needed. The host activity must extend `AppCompatActivity`.

Resolution order: explicit app locale, then device language, then English. Only the language subtag is compared.

## Naming convention

`<feature>_<screen>_<thing>`, for example `example_home_features_title`, `settings_theme_system`.
Shared words use `common_<kind>_<thing>` (for example `common_action_save`); strings owned by reusable components use `component_<thing>` (for example `component_back`).
Language names are not resources; they come from `AppLanguage.nativeName` so each shows in its own language.

## Adding a language

1. Create `app/src/main/res/values-xx/strings.xml` with every key from `values/strings.xml`.
2. Add an entry to `AppLanguage` (`XX("xx", "Native name")`).
3. Run `./gradlew test`. `TranslationCompletenessTest` (in `:app`, it reads every module's `values/` and `values-in/`) fails if keys or format placeholders
   (`%s`, `%1$d`, ...) differ between languages. Extend it to cover the new folder.
